# LEARNING-PROFILE-01 整合驗收案例（外部獨立驗收用）

**用途**：內部交出串接版本後，由外部獨立驗收整個流程，不只驗收計算模組。

**依據**：lp-rules-v1.1、協調人 2026-11-18 的五項決定、event-schema.json、INTEGRATION.md。

**驗收方式**

- 每案都要附 390px 手機畫面截圖。
- 「預期值」一律由 `acceptance/oracle.cjs` 從存檔匯出計算，和面板上的每一格逐字比對。
- 有標「真機」的項目，模擬環境不能代替真機驗收。

**判定**

- **通過**：所有步驟都符合。
- **不通過**：附重現步驟、截圖和存檔匯出。
- **缺證據**：交件中沒有能驗證這一案的入口或資料。

## A. 存檔相容

| # | 步驟 | 預期 |
| --- | --- | --- |
| A1 | 用舊存檔（只有 pm-cards、pm-sents 等，沒有 pm-ability-v1）開啟遊戲與能力面板 | 每格顯示「尚待評估」；顯示舊紀錄的答對詞數與句數；**不**出現任何百分比 |
| A2 | 開啟面板前後比對所有舊 pm-* 鍵 | 內容完全相同 |
| A3 | 重新整理頁面 | pm-ability-v1 和面板內容不變（oracle 比對一致） |

## B. 作答 → 紀錄（文法題，NPC 任務入口）

| # | 步驟 | 預期 |
| --- | --- | --- |
| B1 | 在 NPC 任務答一題文法題，第一次就答對 | pm-ability-v1 只新增**一筆**事件，欄位為：`item: g:…`、`qtype: grammar:form-choice`、`ctx: grammar:<主題>/<次主題>`、`via: npc:<任務 id>`、`result: correct` |
| B2 | 作答前檢查畫面 | 有情境和時間線索；**沒有**時態名稱，例如「過去式」「現在進行式」「going to」等標示 |
| B3 | 作答後檢查畫面 | 有中文、正確句子、發音按鈕和簡短文法解說（`explain`） |
| B4 | 第一次答錯、重試後答對 | 仍然只有一筆事件：`result: wrong`、`retries: 1`、`final: correct`；面板中這題算答錯 |
| B5 | 作答前使用提示 | 事件記為 `hint: true`；面板依據的「排除：提示」數量加 1 |
| B6 | 讓時間用完（有限時的入口） | 事件記為 `result: timeout`；不列入最近錯誤；面板依據的超時數量加 1 |
| B7 | 24 小時內再答同一題 | 會記錄這次作答，但面板依據的「排除：重複」數量加 1，題數不增加 |
| B8 | 用 `oracle.cjs --check-events` 檢查存檔 | 沒有任何 PROBLEM：id 不重複、格式正確、題目存在、文法題的 ctx 正確 |

## C. 分析（面板）

| # | 步驟 | 預期 |
| --- | --- | --- |
| C1 | 匯入測試存檔，內容是過去簡單式 6 題、跨 2 天、4 種情境、4 對 2 錯 | 「過去簡單式・文法辨識掌握度」顯示「65%（發展中）· 6 題、4 種情境」；點開詳細顯示「6 題中答對 4 題＝66.7%」 |
| C2 | 只有 3 題的能力 | 顯示「證據不足：還需要…」，**不**顯示百分比 |
| C3 | 最新證據是 45 天前、或 120 天前 | 顯示「需要重新確認（上次 NN%，最後練習 …）」，舊資料仍保留 |
| C4 | 文法欄的其他通道 | 只顯示「文法辨識掌握度」；其他通道顯示「這個通道目前沒有題型」，**不能**出現造句或口說的百分比 |
| C5 | 四個能力通道 | 閱讀辨識、聽力理解、句子組合、獨立口說分開顯示，沒有合成一個答對率 |
| C6 | 口說格 | 旁邊顯示「只代表語音辨識吻合，不代表文法或發音完全正確」 |
| C7 | 練習答對率、教材覆蓋率 | 和掌握程度分開，並且有自己的名稱 |
| C8 | 面板上每一格 | 和 oracle 的 `rows` 逐字一致 |

## D. 弱項練習 → 分析更新

| # | 步驟 | 預期 |
| --- | --- | --- |
| D1 | 有一項原始比例低於 70% 且已計分 | 「練習弱項」只列出這一項；證據不足、需要重新確認的項目**不**列入 |
| D2 | 按「練習弱項」 | 進入對應的練習或任務，題目來自該項的最近錯題或同類題 |
| D3 | 完成練習 | 回到原本的位置（地圖與座標）；新增的事件筆數等於作答題數；面板依 oracle 重新計算的結果更新 |

## E. 句子層級事件與多標籤

| # | 步驟 | 預期 |
| --- | --- | --- |
| E1 | 生活情境填空答一題 | 只新增一筆事件：`item: s:<句子>`、`qtype: life:context-blank`、`links.word: w:<重點字>` |
| E2 | 答一題談判句（例如 I think we have a deal.） | 「職場・商務談判」與「會議・確認事項」各增加 1 題；同一主題不會重複計算 |

## F. 保留筆數、備份與還原

| # | 步驟 | 預期 |
| --- | --- | --- |
| F1 | 匯入 4100 筆事件後再答一題 | pm-ability-v1 剩 4000 筆，保留的是最新的 |
| F2 | 備份 | 匯出的檔案包含 pm-ability-v1 |
| F3 | 在已有較新紀錄的裝置上還原舊備份 | 合併成聯集，依 id 去重；裝置上較新的事件沒有遺失；面板和 oracle 一致 |

## G. 戰鬥運用（第二階段）

| # | 步驟 | 預期 |
| --- | --- | --- |
| G1 | 戰鬥中出現文法題 | 只出現已在 NPC 任務學過的句型；作答前不顯示時態名稱；事件記為 `via: battle` |
| G2 | 戰鬥答對後 | 不會因為紀錄或面板而重複攻擊，也不會重複加 XP（和 QA-CARD-01 一起驗收） |

## 真機項目（模擬不能代替）

- 答後的發音播放。
- 實際觸控操作。
- 切到背景再回來後，資料與畫面是否保持。
