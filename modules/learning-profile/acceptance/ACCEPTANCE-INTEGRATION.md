# LEARNING-PROFILE-01 整合驗收案例（外部獨立驗收用）

**用途**：內部交出串接版本後，由外部獨立驗收整個流程，不只驗收計算模組。

**依據**：lp-rules-v1.2（派工 revision 9）、event-schema.json、INTEGRATION.md。

**什麼時候開始**：內部 A-ABILITY-INTEGRATION-01 交出以 batch-03／04 串接的固定版本和匿名測試匯出之後。在那之前，不拿 batch-02 的串接版（752f805）做正式驗收。

## 驗收方式

- 每案都要附 390px 手機畫面截圖。
- **比對數值、狀態和證據，不比文字**。UI 的用語可以和 `describe()` 不同，只要下面這些一致就算對：
  - 狀態
  - 顯示的百分比、原始比例
  - 題數、答對題數、情境數、學習日期數
  - 各種排除的數量
  - 是否列為弱項
  - 還原預覽的數字
- **預期值有三個來源**：
  1. `test/hand-fixtures.json` 的手算值。
  2. 本文寫出算式的數字。
  3. `acceptance/oracle.cjs` 從存檔匯出算出的 `rows`（數值欄位）。
- oracle 和遊戲共用 `profile.js`，所以如果只有 oracle 一致、手算不一致，算**不通過**。
- 「模擬」和「真機」分兩欄記錄；模擬結果不能代替真機項目。

## 判定

- **通過**：所有步驟都符合。
- **不通過**：附重現步驟、截圖和存檔匯出。
- **缺證據**：交件中沒有能驗證這一案的入口或資料。

## A. 存檔相容

| # | 步驟 | 預期 |
| --- | --- | --- |
| A1 | 用舊存檔（只有 pm-cards、pm-sents 等，沒有 pm-ability-v1）開啟遊戲與能力面板 | 每格是「尚待評估」（none）；顯示舊紀錄的答對詞數與句數，數字和 oracle 的 `legacy` 相同；**不**出現任何百分比 |
| A2 | 開啟面板前後比對所有舊 pm-* 鍵 | 內容完全相同 |
| A3 | 重新整理頁面 | pm-ability-v1 和面板的數值不變 |

## B. 作答 → 紀錄（文法題，NPC 任務入口）

| # | 步驟 | 預期 |
| --- | --- | --- |
| B1 | 在 NPC 任務答一題文法題，第一次就答對 | pm-ability-v1 只新增**一筆**事件：`item: g:…`、`qtype: grammar:form-choice`、`ctx` 等於題目的 `grammar:<主題>/<次主題>`、`via: npc:<任務 id>`、`result: correct`、`at` 是 UTC 毫秒 |
| B2 | 作答前檢查畫面 | 有情境和時間線索；**沒有**時態名稱，例如「過去式」「現在進行式」「going to」等標示 |
| B3 | 作答後檢查畫面 | 有中文、正確句子、發音按鈕和簡短文法解說（`explain`） |
| B4 | 第一次答錯、重試後答對（若有可重試的入口） | 只有一筆事件：`result: wrong`、`retries: 1`、`final: correct`；面板中這題算答錯 |
| B5 | 作答前使用提示 | 事件記為 `hint: true`；依據裡的「提示」數量加 1，和輔助、超時分開列 |
| B6 | 讓時間用完（有限時的入口） | 事件記為 `result: timeout`；不列入最近錯誤；依據裡的超時數量加 1 |
| B7 | 24 小時內再答同一題 | 會記錄這次作答；依據裡的「重複」數量加 1；題數和學習日期數**都不增加**（即使跨過台北午夜） |
| B8 | 用 `oracle.cjs --check-events` 檢查存檔 | 沒有任何 PROBLEM：id 不重複、格式正確、題目存在、文法題的 ctx 正確、生活情境有 `links.word` |

## C. 分析（面板）

| # | 步驟 | 預期 |
| --- | --- | --- |
| C1 | 匯入測試存檔：過去簡單式 6 題、跨 2 個台北日期、4 種情境、4 對 2 錯 | 「過去簡單式・文法辨識掌握度」是 scored：顯示 **67%**、等級「發展中」、6 題、4 種情境；詳細裡有 4/6＝66.7%；列為弱項 |
| C2 | 只有 3 題的能力 | 證據不足（insufficient），還差 2 題；**不**顯示百分比，也不列弱項 |
| C3 | 最新證據是 45 天前、或 120 天前 | 需要重新確認（stale），附上次的百分比和最後練習的**台北日期**；舊資料仍保留；不列弱項 |
| C4 | 文法欄的其他通道 | 只有「文法辨識掌握度」有數字；其他通道是「未提供評估」（no-instrument），**不能**出現造句或口說的百分比 |
| C5 | 四個能力通道 | 閱讀辨識、聽力理解、句子組合、獨立口說分開顯示，沒有合成一個答對率 |
| C6 | 口說格 | 旁邊顯示「只代表語音辨識吻合，不代表文法或發音完全正確」 |
| C7 | 練習答對率、教材覆蓋率 | 和掌握程度分開，並且有自己的名稱；不稱為語法成熟度 |
| C8 | 面板上每一格 | 狀態和數值與 oracle 的 `rows`、手算值一致（不比文字） |
| C9 | 匯入 23/33＝69.7% 的存檔（手算 H9） | 顯示 **69.7%**（不是 70%），並列為弱項 |
| C10 | 匯入跨台北午夜的存檔（手算 H3、H4） | H3 是 2 個學習日期、計分；H4 是 1 個學習日期、證據不足 |

## D. 弱項練習 → 分析更新

| # | 步驟 | 預期 |
| --- | --- | --- |
| D1 | 有一項原始比例低於 70% 且已計分 | 「練習弱項」只列出這一項；證據不足、需要重新確認、未提供評估的項目**不**列入 |
| D2 | 按「練習弱項」 | 進入對應的練習或任務，題目來自該項的最近錯題或同類題 |
| D3 | 完成練習 | 回到原本的位置（地圖與座標）；新增的事件筆數等於作答題數；面板的數值依手算和 oracle 更新 |

## E. 句子層級事件與副標籤

| # | 步驟 | 預期 |
| --- | --- | --- |
| E1 | 生活情境填空答一題 | 只新增一筆事件：`item: s:<句子>`、`qtype: life:context-blank`、`links.word: w:<重點字>`；重點字只算覆蓋；時態掌握不變 |
| E2 | 答 I think we have a deal. | 「職場・商務談判」與「會議・確認事項」各增加 1 題；`totals.attempts` 和 `totals.distinctItems` 都只加 1 |
| E3 | 答 Can you deliver by the end of the month? | 只有「職場・商務談判」增加，會議不變（batch-04 已移除這句的會議副標籤） |

## F. 保留筆數、備份與還原

| # | 步驟 | 預期 |
| --- | --- | --- |
| F1 | 匯入 4100 筆事件後再答一題 | pm-ability-v1 剩 4000 筆，保留的是最新的 |
| F2 | 匯入「舊的文法證據＋4000 筆較新事件」（手算 H11） | 被裁掉的文法證據不再計分（該格變成尚待評估）；不會顯示裁切前的百分比 |
| F3 | 備份 | 匯出的檔案包含 pm-ability-v1 |
| F4 | 在已有較新能力紀錄的裝置上做**整份還原** | 確認前的預覽寫出會動到的鍵，以及裝置上會消失的能力紀錄筆數；確認後 pm-ability-v1 等於備份內容（裝置較新的紀錄不保留，這是預期行為）；面板數值依新資料重算 |
| F5 | 若有**僅合併能力紀錄**：用含一筆同 id 不同內容的備份 | 預覽寫出新增、重複、衝突（列 id）、裁切數；確認後只有 pm-ability-v1 改變；衝突的那筆保留裝置上的原資料；其他 pm-* 鍵不變 |
| F6 | 還原格式錯誤的備份（重複 id、超過 4000 筆、result 不合法） | 預覽就擋下，不能確認；所有鍵都不變 |
| F7 | 模擬寫入失敗（例如在第二個鍵丟出 QuotaExceededError） | 所有鍵回到還原前的值，沒有半套還原 |
| F8 | 沒有經過預覽和確認就還原 | 不應該發生：任何還原入口都要先顯示預覽 |

## G. 戰鬥運用（第二階段）

| # | 步驟 | 預期 |
| --- | --- | --- |
| G1 | 戰鬥中出現文法題 | 只出現已在 NPC 任務學過的句型；作答前不顯示時態名稱；事件記為 `via: battle` |
| G2 | 戰鬥答對後 | 不會因為紀錄或面板而重複攻擊，也不會重複加 XP（和 QA-CARD-01 一起驗收） |

## 真機項目（模擬不能代替，另外一欄記錄）

- 答後的發音播放。
- 實際觸控操作。
- 切到背景再回來後，資料與畫面是否保持。
- 實際裝置上的備份檔匯出、匯入（檔案選擇器、下載）。
